# Evidence policy

`TARGET` and `ACTUAL` are different fields. An actual value is written only by an executed command
or inspected external resource and includes:

- claim ID and evidence level;
- command/tool and exit status;
- UTC timestamp and environment;
- commit or source-tree identity;
- input/output hashes or exact external run/resource IDs;
- measured value and limitations.

Local mocks, dbt parse, Terraform validation and Docker builds are useful evidence but never count as
Salesforce/GCP runtime proof. Generated payloads are reproducible and must not include credentials,
private identifiers or unlicensed bulk data.

The sustained scorecard remains empty until an owner-approved 7-14 day run is completed. Failed
acceptance gates remain visible; evidence is not edited to make a claim green.

Current committed evidence:

- [`identity_evaluation.json`](identity_evaluation.json): frozen synthetic held-out evaluation with
  source hashes and confidence intervals.
- [`public_source_validation.json`](public_source_validation.json): bounded live public-source HTTP
  acquisitions with hashes and licence limitations; raw responses are not committed.
- [`vgv_preparation_validation.json`](vgv_preparation_validation.json): owner-supplied browser
  downloads verified against the pinned VGV release, normalized row counts, output hash and
  composite source lineage; HTTP transfer metadata is explicitly unobserved.
- `local_pipeline_validation.json`: deterministic 100-customer vertical-slice report, generated by
  `scripts/collect_pipeline_evidence.py`.
- `local_validation.json`: lint, format, strict typing, tests and measured branch coverage, generated
  by `scripts/collect_local_evidence.py`.
- `platform_validation.json`: local Compose/API/Airflow/dbt/Terraform/PostgreSQL/image/secret-scan
  checks, generated by `scripts/collect_platform_evidence.py`.
